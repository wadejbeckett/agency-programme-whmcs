# Changelog

## Unreleased (0.3.0)

- The "Agency Programme" card on the client summary page shows the tier badge (with the start state), the qualifying monthly spend, the dry-run note while dry-run is on, and one link to the agency detail page; the next invoice, the progress bar and the change log and profile links moved to the detail page. The client's Profile tab keeps the approval checkbox, who approved and when, the note and the start date; the "Right now" box beside them is gone (owner's ruling), since the same figures sit on the summary card of the same client record (#12).

- The agency detail view (Overview > Detail) is rebuilt as its own class on WHMCS admin markup: a header panel with the tier badge and start state, qualifying monthly spend and counted items, the progress bar and amount to the next tier, who approved the agency and when, the note and when the figures were recalculated; the counted services and add-ons and the upcoming invoices as before (an invoice due before the start date now says "not yet" instead of a zero discount); a new "Discounts applied" table of every record from `mod_agencydiscount_invoices`, newest first (invoice link, date, tier, percentage, base, discount, taxed flag) with "Saved in <year>" from the same query the client area uses and each record marked when it is left out of that total (dry run, invoice cancelled, refunded or deleted, line removed by hand, an earlier year); and links to the client's change log, the profile tab and the Overview. Every string comes from the language file. The line under the Overview table now describes the rows the filter shows (#11).

- `mod_agencydiscount_invoices` gains an index on `client_id`, which the client area page and home panel's "Saved in <year>" query filters on; a fresh install creates it and the upgrade adds it once. Each upgrade step is skipped when its column or index is already there, so a repeated upgrade from the same version (as WHMCS makes after a failure before the version row is written) adds nothing twice and raises nothing; before, a retry from 0.2.0 failed on the 0.2.1 column changes. The upgrade reports one sentence per step that actually ran, so an upgrade from 0.2.1 or 0.2.2 no longer reports the 0.2.1 column changes, and it deletes the unread `keep_data` row that 0.2.1 replaced with `delete_data` (#10).

- The WHMCS Configure form (System Settings > Addon Modules > Agency Programme) now carries only the access list and the three housekeeping settings: write to activity log, change log retention and delete data on deactivate. Tiers, qualifying items, statuses, the mode, the behaviour switches and the invoice line text are edited on the addon's Settings tab only, which no longer shows the activity-log and delete-data switches or the "Advanced: edit as JSON" link. No setting has two homes, so a Configure form left open cannot write old values over a Settings save (this happened on a live install after the 0.2.1 upgrade). The stored rows are unchanged: WHMCS's Configure save leaves undeclared rows alone (seen on a live install), and the engine reads them as before; a settings set without the removed keys, as on a fresh install before the first Settings save, takes the documented defaults (no tiers, nothing counts, dry-run on), the Overview's "Needs attention" panel names the rows with no stored value, and the daily cron writes one activity-log line a day until the Settings tab is saved, so a discount never stops silently (#9).

- The Configuration check tab is gone: the addon page has three tabs (Overview, Settings, Change log), and an old `action=check` link opens the Overview. What it showed lives where it is acted on. The Overview's "Needs attention" panel lists product group, product and add-on ids not found in WHMCS and tiers configured for a currency WHMCS does not have, each linking to Settings. A Settings save lists the same as warnings under its notice (the discount runs without them). The Settings form already flags such ids as "not found in WHMCS" and such a currency's pane as "not a WHMCS currency", a currency without tiers is flagged on its pane and (when an approved agency is in it) in the attention panel, and the tier table is each pane's band preview (#8).

- Stored settings that do not parse (a tiers value or an id left malformed by SQL or an import) no longer lock the addon page behind a message pointing at the Configure form. The page becomes a repair page: a banner lists the problems on every tab, the Settings tab is filled from the stored values with each problem beside its section (a bad tier cell in its row; a tiers value that is not a JSON object shown as stored), the Change log tab works, and the Overview, agency detail and configuration check show the banner alone. A Settings save that validates repairs the configuration (logged as a `settings_changed` entry with a `repaired` list) and the same request renders the normal page. Hooks are unchanged: with an invalid configuration no discount is applied and the problem is logged once per request. The preview harness renders the repair page as `-overview-broken-` and `-settings-broken-` (#7).

## 0.2.2 — 2026-10-30

Audit should-fix items S1, S2, S3, S5, S8, S9 and S10 (retention), the Overview table, and the release tooling. No schema change: see "Upgrade" below.

- A stored invoice line text equal to the 0.2.0 default (`… qualifying items`) now renders as the 0.2.1 default (`… qualifying {items}`). On a production install the 0.2.1 upgrade rewrote the stored text, but a Settings form opened at the same time was filled with the old value and its Save wrote it back; the line then read "on 1 qualifying items" again. The rendering no longer depends on that timing.
- Claiming an invoice, adding its discount lines and recording them now run in one database transaction. Before, a failed line insert after the claim left a placeholder record (amount 0.00, no line) that marked the invoice as handled, so it was never discounted; the failure now rolls the claim, the lines and the records back together, so the invoice carries no half-applied discount and no placeholder record.
- A recalculation (daily cron or invoice time) now writes only its own columns (currency, spend, tier, counts and times). Before, it rewrote the whole agency row from what it had read, so a revoke, note or start-date change saved while it ran could be undone.
- The client area's "Saved in <year>" now counts a discount only while its line is still on the invoice and the invoice is not Cancelled or Refunded. Before, it summed every applied record, so a cancelled invoice or a discount line removed by hand still counted. Both lines of a mixed-tax invoice still count.
- The development-only classes (the in-memory repository, the frozen clock, the recording activity log, the snapshot loader and the CLI) moved from the module folder to `bin/lib/`, loaded by `bin/lib/bootstrap.php` for the CLI, the tests and the preview harness. WHMCS no longer parses them on every request, and the module folder (41 files) no longer ships them.
- Change log retention: a new setting "Change log retention (months)" (`log_retention_months`, default 24) makes the daily cron remove change log entries older than that. 0 keeps the log forever, and so does a value that is not a whole number from 0 to 600, so a mistyped value never deletes history and never stops the discounts. Approvals and invoice records are never removed.
- Overview agencies table: five columns instead of nine, so no cell runs past two lines at 1440 pixels wide. The currency column is gone (every amount carries its currency), the start state and the detail link sit under the tier badge, the next invoice shows its date with the discount on a second line, and the recalculation time moved to the spend's tooltip and one line under the table.
- `tools/release.sh VERSION` builds the release archive (`agency-programme-whmcs-VERSION.zip`: the module folder plus LICENSE, README and CHANGELOG, checked against the files tracked at the tag) with a `.sha256`, and pushing a `v*` tag publishes it as a GitHub release.
- The sandbox integration test now covers the repository paths above on MariaDB (saved-this-year with cancelled, refunded, hand-removed, mixed-tax and dry-run cases; transaction rollback; recalculation columns; pruning), and the preview harness fixture uses round demo figures.
- `whmcs.json` now carries the feature list and the support links (project home, documentation, issues) that WHMCS's Apps & Integrations pages read; a logo and a support email are still to come. The README's "What has and has not been verified" list records what the live installs since 12 October 2026 have shown.

Upgrade to 0.3.0: the invoice records table gains the `idx_client` index (added once, checked before adding). Nine settings moved off the Configure form (tiers, product groups, products, add-ons, statuses, dry-run, stack with promotions, new orders, invoice line text) and are edited on Addons > Agency Programme > Settings; their stored rows are kept and read as before, and the upgrade logs one line saying so. The unread `keep_data` row is deleted. Replace the whole `modules/addons/agencydiscount` directory; `agencydiscount_upgrade` runs when System Settings > Addon Modules is opened. To reverse: put the 0.2.2 files back (the index can stay; the Configure form shows the nine settings again from their unchanged rows, so the two-homes risk of a stale Configure form returns until the upgrade is redone; `keep_data` is not needed by 0.2.2 either).

Upgrade to 0.2.2: no table changes. `log_retention_months` is a new setting on the Configure form (default 24; it is read as 24 when the row is absent). Replace the whole `modules/addons/agencydiscount` directory rather than copying the new folder over the old one, so the five files moved to `bin/lib/` leave the install; `agencydiscount_upgrade` from 0.2.1 records "no schema change".

## 0.2.1 — 2026-10-27

Fixes from the 27 October 2026 production-readiness audit, and the work on `main` after the 0.2.0 deploy. The upgrade changes one table: see "Upgrade" below.

- Invoice line grammar: the line text has a new `{items}` placeholder that reads "item" for a count of 1 and "items" otherwise, and the default text is now `Agency discount {percent}% on {count} qualifying {items}`, so a one-item invoice no longer reads "on 1 qualifying items". `{count}` and `{percent}` work as before. The Settings tab lists the placeholder and its example uses it.
- Deactivating no longer deletes data by default. The "Keep data on deactivate" setting (`keep_data`, off by default, so deactivating dropped every approval, the change log and the invoice records) is replaced by "Delete module data on deactivate" (`delete_data`, off by default). The tables are dropped only when it is explicitly on; off, a missing setting row or an unrecognised value keeps them. A stored `keep_data` row is left in place and is no longer read.
- Approving an agency needs the addon's access list: the "Agency discount" field on the client's Profile tab is shown only to admin roles on the addon's access list (the check the client summary card already made), and a save from any other role is ignored and noted in the WHMCS activity log.
- Mixed taxed and untaxed lines: an invoice whose discounted lines mix taxed and untaxed items now gets one discount line per tax treatment, each worth the percentage of its own lines and flagged like them. Before, one line was marked taxed when any discounted line was taxed, which lowered the tax by the discount on untaxed items too. An invoice with one tax treatment still gets exactly one line. Both lines are recorded, logged as one `applied` entry with a `lines` list in the detail, summed in the client area's "Saved in <year>", and shown separately by the CLI rehearsal.
- Admin home widget rebuilt the way WHMCS builds its own widgets (`modules/widgets/`): an `icon-stats` block of four figures (spend per month, discount in the next 35 days, agencies at a tier, mode) that both admin themes style like the Support widget's, the agency list inside the theme's `widget-content-padded` scroll box with two short lines per agency (name and spend; tier badge and next discount or start date), and a footer with the last cron check and a link to the addon. No theme rule is overridden; the module's own styles cover only the footer and the two-line rows. The widget id is `AgencyProgramme` (the dashboard's refresh, minimise and hide buttons need an id without a namespace). Requires the "View Income Totals" permission and a role on the addon's access list; a failure renders one line and goes to the activity log.
- Client summary card: the slim progress bar now carries its own style.
- `tools/preview/`: an offline render harness that wraps the home widget (next to stand-ins built from the Billing and Support widgets' markup), the overview and settings tabs and the client summary card in a WHMCS admin theme's frame (theme files referenced by path, not shipped) for headless-browser screenshots.
- The example profile is now the generic `profiles/example.json` (placeholder ids, USD tiers) instead of one installation's settings, and `tests/ProfilesTest.php` checks every file under the module (including `lib/ClientArea`, `templates` and `lang`) with generic host-name and currency patterns, and the profiles for installation-specific values.
- Fixed: a counted service or add-on with a negative recurring amount made the agency's recalculation throw, so its invoices were not discounted and the dashboards failed. The negative amount now keeps its sign in the monthly equivalent and is left out of the upcoming-invoice estimate, as it already was on the invoice.

Upgrade: `agencydiscount_upgrade` now branches on the installed version. From below 0.2.1 it changes `mod_agencydiscount_invoices` to hold one row per discount line (an auto-increment `id` primary key, a `line` number with a unique key on `invoice_id` and `line` that keeps the first-writer-wins claim, and a `taxed` flag filled from each record's invoice line), and rewrites the stored invoice line text to the new default only when it is still the old default exactly. Each change is written to the WHMCS activity log.

## 0.2.0 — 2026-10-13

Dashboards for the programme, on every WHMCS surface an administrator or an agency sees. No schema change: `agencydiscount_upgrade` logs the upgrade and leaves the tables as they are.

- Settings tab on the addon page: mode card with a dry-run / live switch, a tier table per currency with add, remove, band preview and "copy at the WHMCS rate", product group, product, add-on and status pickers by name, the behaviour switches and invoice line text, an impact preview of every approved agency under the unsaved values, and a save that validates, reports problems inline and logs `settings_changed`. The saved keys are unchanged, so the raw Configure form (now the advanced route) and the CLI profile stay valid.
- Overview tab redesigned: tiles for approved agencies (at a tier, waiting for a start date), qualifying spend per month and the discount expected in the next 35 days per currency, and the mode; the agencies table with a tier badge, a progress bar and the amount to the next tier, the next invoice and its discount, flags for a start date and for a currency without tiers, filters (all, at a tier, not yet started, no tiers for currency) and a client-name search; a side column with what needs attention (dry-run age, currencies without tiers, agencies within 5% of the next threshold) and the six most recent change-log entries as sentences. The change log tab shows the same sentence as a Summary column.
- Admin home widget (`AdminHomeWidgets`): agencies, spend per month, discount in the next 35 days, mode badge, one row per agency, last cron check and a link to the addon. Requires the "View Income Totals" permission and a role on the addon's access list; a failure renders one line and goes to the activity log.
- Client summary card (`AdminAreaClientSummaryPage`) for approved agencies: status badge, spend, next invoice saving, distance to the next tier, dry-run note and links to the counted items, the change log and the profile tab. Shown only to admin roles on the addon's access list.
- Profile tab: "Approved by <admin> on <date>" under the checkbox, the start-date explanation, and a live "Right now" box (spend, tier, next invoice, progress to the next tier) beside the fields. The field names are unchanged.
- Client area, read-only and visible to approved agencies only: a home panel (`ClientAreaHomepagePanels`) with tier, spend, next-invoice discount, saved this year and the amount to the next tier, and a module page (`index.php?m=agencydiscount`) with the tier table marked "You are here", what counts and what does not, the counted services and add-ons with monthly equivalents and totals, and the discount saved this calendar year. Styled by the client theme (Bootstrap 4 classes).
- Repository: product groups with active-service counts, products, add-on catalogue, currencies with rate and default flag, settings writes, the count of invoices checked, an admin's role id and the applied discount total of a client from a date.
- Fixed: names stored HTML-encoded by WHMCS (an add-on called "... CDN &amp; DDoS") were escaped a second time on the Configuration check and agency detail pages.

## 0.1.0 — unreleased

- Initial Agency Programme addon: approval flag on the client profile with an optional start date, qualifying spend and tier engine, discount line added to invoices on creation, dry-run mode, admin overview, agency detail and configuration check pages, change log, CLI rehearsal against a database snapshot, and an example profile. New orders of approved agencies are discounted too (setting `new_orders`, on by default): the pending items on the order invoice join the discount base and the tier is chosen on the counted spend plus their monthly equivalent.

### Known limitations / planned for 0.2

- Split the discount line into a taxed and an untaxed part when the discounted lines are mixed (today the whole line is taxed if any discounted line was).
- Recalculation writes the whole agency row, so it can overwrite an approval change made at the same moment; update only the computed columns.
- Filter the change log by event.
- An admin "apply to invoice" action for unpaid invoices that were skipped while dry-run was on.
- Show claim placeholder records (no item id) on the admin page.
- Branch `_upgrade` on the previous version once a release changes the schema.
